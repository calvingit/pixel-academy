# 数字花园接入验证

执行者：Codex 代理；日期：2026-10-26。本次提交包含代码、文档、验证脚本与 JSON 结果，不代表已经部署或 M7 完成。图片按用户要求仅保留本地，文中的截图链接在其他检出环境中可能不可用。

## 实现与检查

- 正式入口采用薄荷绿掌机、木牌标题、数字花园、蓝蓝与蓝色数字块；维持 360×620 逻辑画布、3×4 棋盘、现有题库及存储格式。其他八款未接入。
- `npm run check`：74 项通过，0 失败（原有 73 项 + 花园绘图测试）。新增测试检查坐标、画布范围与 Canvas 状态栈平衡；静态模块由构建纳入预缓存，共 19 个资源。
- 首轮花园测试发现侧边树冠越过底边，修正后通过。端到端连点发现现有入口在最后一题 resolving 阶段读取越界的题目；增加 asking 阶段检查后，在线／离线两局均包含最后一题连续派发三次 pointerdown，最终错误收集为空。
- 对比度复查发现木牌副标题与机身小字不足 4.5:1，已改为深墨色；主要反馈文字／题卡色组合均达到 4.5:1。
- `git diff --check`：通过。未更改判题、题库审核、存储格式或离线更新策略。

## 浏览器回归

环境：macOS，ego-browser Chromium；视口模拟，不是真实移动设备。运行入口 `http://127.0.0.1:4175/`。浏览器版本另见 [环境与补充检查](supplement-results.json)。

复现：先执行 `npm run serve -- 4175`，再执行 `ego-browser nodejs < docs/evidence/game-style/browser-check.mjs`。脚本使用本地测试 origin 的正式题集和本地记录，不清除记录。结果见 [browser-results.json](browser-results.json)。

- 五档视口：320×568、390×844、412×915、568×320、1280×900。无页面横向溢出；最小数字块约 75.6×61.6 CSS px，最小局内按钮边长 48 CSS px。低高度下页面纵向滚动，完整页面截图不表示内容都能在首屏看到。
- 暂停／继续、刷新后恢复同一 recordId 与相同 round 状态、三次答错、反馈窗口连点、消除窗口连点、正式结算、再来一局得分归零及返回记录：通过。
- 混选一、二年级 10 题局：总分 95，一次通过 9/10，答错 3 次；新增恰一条成绩，错误收集为空。完整逐题任务与选择记录见 JSON。
- CDP 网络离线后重新加载页面，二年级 6 题局：总分 60，一次通过 6/6，答错 0 次；新增恰一条离线成绩，navigator.onLine 为 false，错误收集为空。
- 查看了普通算式、连续加减、2／3／5 行乘法点阵截图；最大五行点阵与题下文案分离，没有被装饰覆盖。暂停、选择、结算与记录截图已目视复查。

操作边界：年级选择、恢复等部分操作使用浏览器原生点击；主要控制回归使用页面内 DOM click，棋盘通过页面实际边界换算逻辑坐标后派发 pointerdown。自动化工具在原生操作前会短暂触发真实 visibilitychange，已观察到后台自动暂停与回前台保持暂停。脚本等待 phase 回到 asking 后再作答；早期驱动脚本仅等待 questionIndex 变化，会在 resolving 期间提前点击，已修正，未将该驱动超时视作游戏缺陷。

补充检查：三年级空内容禁用开始、混选一年级与三年级仅提供一年级内容、键盘焦点描边、本地存储不可用提示与主模块加载失败提示，结果见 supplement-results.json。存储不可用通过独立测试页注入读取失败模拟；启动资源失败通过测试页绕过 SW 并阻断主模块模拟，未修改正式数据。
