## 2. 统一边界与交付规则

### 2.1 不变的产品约束

- 每款允许一至六年级任意非空单选、多选。首发内容范围由实际审核结果决定，不预先承诺六年级全覆盖；无内容要明确提示，混选明确实际供题年级，不跨年级补题。
- 正式练习必须经过 `selectExercises`；`previewExercises` 只用于显式候选预览。不能因开局缺题把 draft 改为 approved，或把预览当降级路径。
- 数学计算优先经审核规则动态生成；语文、英语、阅读等按实际需要使用经审核固定内容，不机械套用数学生成方式。
- 练习审核与教材来源、地区选用、教学映射核验分开。允许如实记录代理审核，但不得冒充教师，不虚构书名、版次、ISBN、来源、音频审核或学生效果。
- Learning Core 纯 TypeScript；判题不依赖 DOM、Canvas、存储、音频播放回调或服务端，不执行字符串表达式。
- 现有数字消除的 10 秒、复活、道具、金币、课程与领奖规则继续有效。**新游戏不自动继承这些经济和计时规则**；本交接建议新游戏首版不限时、无新增金币奖励与商店商品。接手实施时写进各款玩法文档；用户要求共用经济后再明确奖励契约，不能自行发币或改现有钱包。
- 不新增账号、云同步、排行榜、录音、在线识别、分析 SDK、后台、通用引擎或编辑器。新增依赖先说明必要性并按项目规则获得确认。

### 2.2 每款游戏的执行阶段

| 阶段 | 必须产出 | 进入下一阶段的条件 |
| --- | --- | --- |
| A：规则与内容 | 一局完整示例、首发年级/能力、题量与不足提示、判题/重试/暂停/退出/结算规则；draft 内容和来源记录 | 关键歧义已解决；不能把候选映射当教学结论 |
| B：窄路径验证 | 一道真实经审核练习，经正式筛选 → 界面输入 → Core 判题 → 游戏状态 → 保存恢复 → 离线重开 | 实际打通所需边界；测试 fixture 仅用于测试，不代表正式内容可用 |
| C：首版交付 | 该款约定的全部模式与首批内容、手机交互、完整局次、记录/恢复/离线/更新 | 全部本款验收项有结果；窄路径成功不能代替首版验收 |
| D：回归与记录 | 相关自动化、实际浏览器流程和目视截图、已交付游戏回归、设备覆盖与缺口 | 更新 PLAN；只有条件全部满足或用户明确裁决例外才标完成 |

每款在 A 阶段把题量与开局阈值写成具体数值，按审核可用内容选择最小完整局，不能使用“足够数量”作为验收标准。建议短局 5 个任务，内容不足则阻止开局或明确缩短局次并说明，具体方案在该款玩法文档中固定，不沿用数字消除必须 10 题的规则。该建议尚不是已确认产品规则。

重大新 UI 先在已有风格原型上确定方向并查看渲染，再接入规则。各款保留各自主题，导航、题卡、选中/禁用/反馈/暂停沿用现有规范；汉字、拼音、英语和短文不强制像素字体。普通操作优先 DOM 控件，拖拽提供点选放置替代，不以颜色、声音或动画单独传递结果。

### 2.3 首次多游戏接入必须处理的影响面（随 M8 落地）

以下是具体实施范围，不要求预建框架。先选择最小可行方案并记录理由。

| 边界 | 当前事实 | 接手动作与验收 |
| --- | --- | --- |
| 类型与判题 | Exercise.subject 固定 math，MathTask 只有数学；SubmittedAnswer 是数值/字符串/字符串数组 | 增加按学科/任务区分的联合类型，保留现有数学语义；仅增加当前游戏需要的任务，禁止万能 payload、强制类型断言和字符串执行 |
| Core 与导出 | validateCatalog 对每题调用 validateTask，selectExercises 按学科/年级/gameId 筛选 | 同步任务校验、学科一致性、判题和导出；测试非法跨学科任务、草稿隔离、未知游戏、63 种年级组合 |
| 数字消除调用方 | rules、generation、learning、render、storage、profile 等直接使用 Exercise/MathTask | 搜索全部调用方并收窄数学类型，保证新增语文练习不会进入数字消除棋盘或数学错题解析 |
| 入口与导航 | 正式首页仍是数字消除；game-style 独立且未接正式规则 | 增加最小游戏选择和返回路径，保留数字消除可达、原预览隔离及刷新恢复；未交付游戏不显示可玩入口，不用展示原型代替正式入口 |
| 本地数据 | IndexedDB pixel-academy / profiles / local，Profile schemaVersion 2；challenge、practice、错题与解析均绑定数学；旧 localStorage 只读导入 | 首款新游戏优先独立命名空间存局次和记录，避免为它改造钱包。需要共享档案时先列字段、调用方和迁移方案；不得覆盖数学 challenge/practice 或清空旧档案 |
| 记录语义 | 数字消除成绩不是通用学习能力评估 | 新游戏记录 gameId、局次 ID、题目/内容版本、实际作答、首答/重试及完成结果；原题可恢复、重复结束不重复记账；不据分数宣称掌握 |
| 离线构建 | build-sw 仅从 dist/game/number-puzzle/main.js 解析静态 import；只显式登记 / 与 /style.css | 根据实际新入口扩展模块闭包与静态资源清单，覆盖图片、音频、字体；动态 import、HTML 资源和运行时 URL 不会自动被现有闭包收集。新增资源要真实存在、参与哈希、缺失时构建或缓存明确失败 |
| 服务与部署 | serve 绑定 127.0.0.1，MIME 表尚无音频项；路径默认根目录 | 听辨接入时补所需 MIME；真机不能直接访问电脑的 127.0.0.1，也不能把普通 LAN HTTP 当成完整 SW 安全上下文。按已确认的 HTTPS 测试环境处理，不擅自公开服务 |
| 更新时机 | 当前安全采用判断只围绕数字消除屏幕及活动局次 | 新游戏的活动/暂停局次都阻止主动采用更新；返回安全入口后切换。测试新旧资源不混局、缓存清理不误删其他应用 |

不得提前实现八款任务模型或通用游戏接口。M8 出现实际复用时仅提取导航、筛选提示等必要部分；M9 再接音频，M11 再接图形操作，M15 再接证据选择。目录名称和模块拆分沿用实际代码；本文的新文件建议不是既有实现。

## 5. M9：拼音冒险

### 5.1 首版范围与内容

- 从声母/韵母辨认（MAP-003/004）起步，分开组织字形辨认与声音听辨。具体音节、声调、整体认读、拼读只在规则与内容审核覆盖后添加。
- 云端飞行主题用于进度反馈，首版不做反应速度驱动的飞行障碍；答题仍用清晰控件。
- 教学音频必须是随构建交付、发音和标记核对过的资源，登记来源/许可、说话者或合成身份、审核者与范围。不依赖在线 TTS，也不能假定浏览器语音能离线且发音一致。

### 5.2 执行切片

1. 定义辨认和听辨各一局示例、重播/重试规则。审核字母形态、变音符、音与字母/音节的对应，不把字母名称与目标教学发音混用。
2. 一道已审核听辨题端到端打通：用户手势启动音频 → 重播 → 选项提交 → 判题 → 恢复 → 断网重播，先证明真机音频与缓存可行。
3. 扩充两种模式。听辨页面不显示答案文字，资源 URL、可见标签与辅助描述不额外暴露正确选项；不隐藏正常的可访问操作标签。
4. 区分教学语音和反馈音效；处理系统静音/播放拒绝/解码失败，提供状态、重试、退出或切换可用辨认模式。听辨不可播放时不能记作完成。
5. 补音频 MIME、预缓存、资源版本、暂停/后台停止播放及恢复后重新播放，不叠音、不因播放回调重复推进题目。

### 5.3 测试与验收

- 测试题目与资源一一对应、错误选项、重复点击播放、播放拒绝/资源缺失、恢复后题目一致；音频文件存在与 MIME 正确纳入检查。
- 实际听辨整局、断网关闭重开后整局，检查可重播、无文本泄题；目视检查 ā/á/ǎ/à、ü 等实际使用字形。
- iOS Safari 与 Android Chrome 分别检验手势解锁、后台、耳机/扬声器实际可听性，不能用 WebAudio 状态或波形代替真人试听与发音审核。
- 发音资源或真实审核不足时保持听辨受阻；辨认可单独留证，不将 M9 整体标完成。首版不做录音与自动发音评分。

## 6. M10：英语快递员

### 6.1 首版范围与内容

- 从 EN-01A 现有家庭成员/状态感受候选能力（MAP-015/016）核对，按实际审核决定首批任务。展示原型 apple/pear 不是现有教材覆盖证明；新增物品主题须补明确知识点、映射及审核。
- 玩家读或听短任务，选包裹/对象并送达目标；用少量固定地点和点选移动，无自由寻路或复杂地图。
- 建议先交付经审核文字指令，再加入有资源的音频模式；若首版规则承诺听力，则必须完成相应审核和离线验收才能标该模式完成。

### 6.2 执行切片

1. 为每条任务定义指令、物品、收件人/地点、可接受组合、干扰对象、反馈与语言能力。家庭/情绪任务须采用自然且可解释情境，不为送达玩法牵强改写英语。
2. 打通一个包裹选择 → 目标选择 → 送达校验 → 记录的真实任务；区分选对物品但送错对象、选错物品却送对地点。
3. 完成短路线、多任务、错误后可纠正、返回和重试；随机化目标位置但同一中断任务恢复后位置保持一致。
4. 图片/语音按内容流程记录来源与许可；听力不默认展示答案文字，播放失败沿用 M9 的明确状态处理。
5. 保存包裹、目标、任务进度与已送达记录，离线后能完整交付。

### 6.3 测试与验收

- 正确物品+正确目标才能完成，错对象/重复送达/连点不完成或不重复计分；所有合法组合和干扰组合有用例。
- 手机完成读指令、取物、送达、纠错、结算、重开、暂停刷新恢复和断网局；截图核对英文可读、目标不被角色遮挡。
- 统计语言作答与移动操作分开，不将随意走到固定位置算作理解；不添加口语评分。

## 7. M11：几何建筑师

### 7.1 首版范围与内容

- 图形辨认、分类、按目标简单搭建；二维拼图归本款，旋转/图形运动仅在内容审核明确后扩展。
- 现有 MAP-009 是分类候选；立体图形能力目前缺少对应知识点，必须依据实际来源新增，不能宣称已有覆盖。平面图形与立体对象使用不同表述。
- 视觉参考积木工坊。投影、透视和装饰不得让训练目标混淆；首版无需三维或物理引擎。

### 7.2 执行切片

1. 明确形状/对象数据、尺寸、方向、分类依据、目标槽位、旋转许可、接受误差与等价摆法，附一个多解例和一个错误例。
2. 一块积木通过点选放置和拖拽两条路径完成同一真实任务，检查缩放坐标、触摸取消和边界命中，再扩充内容。
3. 接入辨认、分类与简单搭建；判题基于形状、关系或槽位语义，不能只比截图像素或唯一操作顺序。
4. 错放可撤回，拖出边界、触摸中断和旋转不造成丢块；恢复保存当前布局、方向与选中状态。
5. 按多屏幕布局、滚动冲突、离线资源和内容版本完成交付。

### 7.3 测试与验收

- 覆盖等价正确解、错误分类、旋转对称、允许/禁止旋转、容差边界、重复放置、拖拽取消、同一坐标转换下的绘制/命中一致性。
- 手机实际拖拽和点选放置均可完成一局；横竖屏切换、暂停/刷新后布局一致。真实触摸结果与鼠标/桌面触摸模拟分别记录。
- 图片不混淆圆与球、正方形与正方体等实际采用的训练对象；内容审核覆盖最终渲染图，不只看源数据。

## 8. M12：算术地下城

### 8.1 首版范围与内容

- 使用经审核数学范围，小规模房间、简单选路和运算解锁；计算答案实际决定开门或资源分配，不能只是与探索无关的答题弹窗。
- 优先复用 Learning Core 的整数判题和已审核运算范围。数字消除生成器具有自己的 gameId、组卷和审核范围，不直接改 gameId 就复用；新增适配范围必须审核。
- 不增加职业、装备养成、复杂战斗、付费资源、程序化大地图。探索资源与原金币钱包分开，首版不新增金币奖励。

### 8.2 执行切片

1. 定义最小固定房间图、起点/终点、门与答案关系、资源流转、错误重试和退出规则，附逐房间的一局示例。
2. 一道规则生成题通过正式筛选开门并进入下一房间，保存后断网恢复，证明运算确实影响探索状态。
3. 加入小规模分支和资源选择；任何允许的选择都保留完成或明确重试路径，不能答错一次永久锁死。
4. 记录题目答案/首答与探索决策，分别显示作答表现和探索结果；恢复保存房间、门、资源、已完成练习和 RNG 状态（若使用随机）。
5. 对完整状态空间或可解释的有限范围检查可达性，再做整局浏览器验收。

### 8.3 测试与验收

- 覆盖门条件、错误答案不解锁、重复解锁不重复资源、资源边界、多条路径、回退和恢复，动态题合法边界和确定性。
- 固定小图可穷举；如加入随机，记录种子并覆盖可达性，不能只测一条顺利路线。
- 浏览器完成主路径、分支、答错恢复、刷新和断网；现有数字消除的候选配额、成绩和钱包不变。

## 9. M13：单词冒险岛

### 9.1 首版范围与内容

- 依据已审核词汇、短语或简短情境线索寻物，重点是理解线索并定位目标，与快递员的明确指令送达区分。
- 现有英语知识点主要是家庭/感受，不能把原型 BANANA 当成正式词库。先检查能否形成真实寻物任务，需要新增主题时逐批补映射和审核。
- 单词跑酷保留为后续变体，不加入首版；不依赖联网词典、翻译或远程语音。

### 9.2 执行切片

1. 与 M10 的玩法文档对照，写出差异和一局线索示例。若实际任务只有“读目标词 → 点同词”，先提出合并为 M10 模式并由用户裁决，不能自行取消 M13 或复制一套仅换皮游戏。
2. 一条原创已审核线索 → 选择场景目标 → 可解释判题 → 反馈与记录，打通正式筛选和离线。
3. 扩充小场景、多线索与合理干扰项；必要词汇均在所选范围，装饰文字不能成为额外必懂指令。
4. 目标位置变换不改变答案身份；提示揭示后标记辅助完成，不能混作独立首答。保存目标布局、已找到项和提示状态。

### 9.3 测试与验收

- 审核线索与目标一一对应或显式多解，不因相同图片名称造成歧义；用例覆盖干扰物、重复找到、提示和中断恢复。
- 浏览器完成整局寻物、错误纠正、提示、横竖屏切换、刷新和断网；不同位置布局下仍按语言含义判题。
- 完成记录单独列线索理解与提示使用，不把点击速度作为词汇掌握结论。

## 10. M14：成语大冒险

### 10.1 首版范围与内容

- 成语补全、字序辨认、语境选择驱动的小迷宫；不是只把四字摆在页面。三种能力分别组织并记录。
- 当前没有成语知识点，新增词条、解释、例句/短情境、目标年级及映射必须有独立依据；不能从一年级识字目录推导成语范围。
- 原型“守株待兔”仅供视觉参考；词条和故事说明需真实审核，版权和来源明确。

### 10.2 执行切片

1. 明确成语、释义、接受字序/填空、适用语境、干扰依据及纠错解释，逐项审核，固定首版各模式的任务数。
2. 一道已审核语境题或补全题正确打开迷宫门，答错可重试、走到终点才结算，先验证学习与路线关联。
3. 补全三种模式；重复字用稳定字卡 ID 区分实例，但判题按答案语义接受等价交换，不被拖拽顺序误判。
4. 使用小型可达迷宫，答题点不可被旁路绕过；保存位置、开门、字卡和作答进度，完成离线与恢复。

### 10.3 测试与验收

- 覆盖唯一/多解补全、重复字、错序、近义/相似成语干扰与语境歧义；解释须支持排除错误选项。
- 验证起终点可达、答错可恢复、不能绕过必须练习、重复入门不重复计分；恢复不会重新打开已完成题目领奖。
- 浏览器完整覆盖三模式与错误纠正，中文清晰、迷宫不遮挡长语境；无审核年级保持未开放。

## 11. M15：文字侦探

### 11.1 首版范围与内容

- 从 MAP-005“提取明显文本信息”候选能力起步，按篇审核来源明确或原创短文、问题、答案及证据。
- 玩家阅读 → 选择/标记证据 → 作答 → 查看依据。首版仅显性信息，不做开放主观题或依靠常识补全的推理；不限时阅读。
- 以可读短文与侦探笔记为主，提供句子/片段级点选，避免让孩子在手机上精确拖动文本选区。

### 11.2 执行切片

1. 每篇定义稳定文本/句段 ID、文本版本、问题、可接受答案与证据集合；既支持多个正确片段，也说明是否必须多片段联合支持。
2. 一道真实题完成阅读、点选证据、提交答案、联合校验、反馈、保存与离线。规则明确“答案对但证据错”和“证据对但答案错”如何反馈，不能只验答案。
3. 扩充经审核短文与提问；同文多个问题记录独立，答案依据不可由装饰提示或固定选项位置泄露。
4. 保存阅读位置、证据选择、作答与题目版本；编辑正文不能让旧偏移静默指到别的文字，内容不兼容按现有安全策略提示处理，不破坏历史记录。
5. 阅读区可滚动，证据操作、提交和返回易找到；暂停恢复、刷新和断网流程完整。

### 11.3 测试与验收

- 覆盖同义合理答案、多个可接受证据、联合证据、只答对/只选对证据、越界/失效句段 ID、重复提交及正文版本变化。
- 每题均能由原文支持，审核记录包含原文位置；不能仅做字符串相等测试来证明语义正确。
- 手机实际阅读和取证不与滚动冲突，放大/长文本不截断，完成一篇多题、纠错、恢复和离线整局；不以倒计时作为唯一过关条件。
