日期：2026-10-26。

状态：已按用户后续授权实施全部 17 类题型，已完成自动化及桌面浏览器验证。用户明确本次一并完成首批与后续扩展；当前年级、数域及代理审核范围见 [扩展审核](content-review-question-expansion.md)，浏览器与自动化证据见 [扩展验证](evidence/question-expansion/README.md)。真实设备、教师评审与教学有效性仍未验证。

## 目标与边界

将数学练习从“算出一个整数”扩展为比较、筛选、判断、计算和简单推理，通过单选、多选、对错三种作答方式丰富训练。

- 保留任意单选、多选年级，只使用所选年级实际审核通过的内容；不跨年级补题。
- 优先按经审核的数值边界和规则动态生成；固定题目用于说明、回归或必须固定的场景。
- 沿用数字花园视觉、课程、错题复习、本地记录和离线能力，不新增独立游戏、后端、通用题型引擎或依赖。
- 题型、作答方式和知识点分别描述：同一知识点可以用不同方式练习，但不能因换了交互就自动视为审核通过。
- 本文示例属于通用原创设计，不宣称对应特定教材版次；年级归属、知识点关联和数值范围须逐类审核后确定。

## 实施前基准

实施前 `MathTask` 只有 `number`、`binary`、`chain`，`answerFor` 返回整数，`evaluateAnswer` 接受整数或十进制整数字符串。游戏通过点击等值数字块立即作答，棋盘、提醒、讲解和存储校验也围绕单一整数答案设计。

实施前玩法暂缓不适合单一整数点选的任务。本次新增 `choice` 和专用题卡，已同步 [现行玩法](gameplay-number-puzzle.md)，原整数 API 保留，不把多选强套到整数棋盘。

多选不能只改题目文字：需要固定选项、选中状态、提交动作和整组判题。对错题和符号选择也不应把布尔值、比较符号伪装成数字答案。

## 题型目录

以下示例只用于说明题意和答案，不是正式题库或审核结论。

| 能力 | 题型 | 示例 | 作答与答案 | 原建议批次 |
| --- | --- | --- | --- | --- |
| 数的比较 | 选较大／较小的数 | 7 和 4，哪个数更大？ | 单选：7 | 首批 |
| 数的比较 | 找最大／最小值 | 找出 3、8、5、6 中最小的数 | 单选：3 | 首批 |
| 数的比较 | 选择比较符号 | 8 ○ 5，选出正确符号 | 单选：＞ | 首批 |
| 数的比较 | 大于指定数 | 找出所有比 6 大的数：3、6、7、9、5、8 | 多选：7、9、8 | 首批 |
| 数的比较 | 小于指定数 | 找出所有比 5 小的数：2、5、7、0、4、6 | 多选：2、0、4 | 首批 |
| 数的比较 | 比较关系判断 | “6 比 9 大”，对不对？ | 对错：错 | 首批 |
| 运算理解 | 计算结果判断 | “7－3＝5”，对不对？ | 对错：错 | 首批 |
| 运算理解 | 未知数填空 | □＋3＝8 | 单选：5 | 首批 |
| 数的比较 | 范围筛选 | 找出所有比 3 大、比 8 小的数：2、3、4、6、8、9 | 多选：4、6 | 第二批 |
| 数的顺序 | 相邻数 | 8 后面的一个数是多少？ | 单选：9 | 第二批 |
| 数的顺序 | 数列补空 | 2、4、6、□、10，每次增加 2 | 单选：8 | 第二批 |
| 数的组成 | 合成与分解 | 8 可以分成 3 和几？ | 单选：5 | 第二批 |
| 数位理解 | 按数位找数 | 找出所有个位是 3 的数：13、30、23、35、43、50 | 多选：13、23、43 | 第二批 |
| 运算理解 | 比较算式结果 | 4＋3 ○ 9－1，选出正确符号 | 单选：＜ | 第二批 |
| 运算理解 | 找等值算式 | 找出所有结果是 8 的算式：5＋3、9－1、6＋1、10－2、4＋3、9－2 | 多选：5＋3、9－1、10－2 | 第二批 |
| 图示理解 | 看图选算式 | 两组圆点，每组 3 个，选择符合图意的算式 | 按明确训练目标确定单选或多选 | 后续审核后 |
| 数量关系 | 简短情境题 | 原来有 7 颗种子，种下 2 颗，还剩几颗？ | 单选：5 | 后续审核后 |

奇偶数、倍数、单位换算、分数和小数比较列为后续方向，本批不展开。不得根据题型名称直接推定教材单元或年级归属。

## 作答与反馈规则

### 单选

- 点击一个选项立即判题，答对后消除并进入下一题。
- 保留原有计算题“任选一个等值数字块即可”的语义。
- 新的单选题使用固定候选，保证有且仅有一个正确选项；最大／最小值题不生成重复极值。
- 比较符号直接显示为可选择的符号，并配合可理解的说明，不复用数字编码。

### 多选

- 点击选中，再次点击取消；提交前不判对错、不消除、不补块。
- 提供固定可见的“提交答案”按钮，空选择时禁用；首批不生成无正确项的题目。
- 首批每题 6 个不重复数字选项，包含 2–4 个正确项和至少 2 个干扰项，不生成全选题。
- 不显示正确项数量或“还差几个”，避免利用提示试探答案。
- 以选项身份判断选中集合；顺序不影响结果，全部正确且没有多选才通过。
- 一次提交算一次作答，按整题计分和奖励，不按选中块数奖励。
- 答对后统一消除选中的正确块，再补块；题目有效期间候选保持不变。
- 选中样式同时使用勾选、边框等标记，不只依赖颜色；键盘和触摸操作遵守同一规则。

### 对错

- 使用带文字的“对 ✓”“错 ✗”两个操作，点击后立即判题。
- 题面先给出完整陈述，不能要求孩子猜测省略条件。
- 正确与错误陈述均须生成后验证，不以位置、颜色或固定答案顺序提供线索。
- 对错题不能单独作为掌握知识点的充分证据；不新增学习能力评级。

### 讲解与复活

- 不限时练习提交后，可区分漏选和多选，并解释每个争议选项的依据。
- 例如“找出所有比 6 大的数”漏选 8、多选 6，应分别说明“8 比 6 大”“6 等于 6，不是比 6 大”。
- 对错题展示正确关系，例如“6 比 9 小，可以写成 6＜9”，不只显示“答错了”。
- 挑战失败后的复活前反馈不直接泄露完整答案；完整讲解可在本题最终结束或错题复习时查看。
- 多选复活重答保留原题与候选，清空选择，避免恢复半份提交；原先提醒卡使用标记继续保留。
- 提醒卡若按现有规则接入，应提示完整正确选项集合，不自动提交；整题视为辅助完成。

## 难度与组卷

比较类建议按“两个数直接比较 → 多个数找极值 → 单条件筛选 → 等于边界辨别 → 双条件或算式比较”递进。不要靠双重否定、绕口文字或过长阅读增加难度。

干扰项围绕明确误区生成，例如大于题包含等于目标数的选项，检验是否混淆“大于”和“大于或等于”。数列使用明确规则和足够已知项，不将开放规律强行判为唯一解。

在所选年级内容均已审核且候选充足时，建议每局 10 题采用以下初始配比：

| 内容 | 题量 |
| --- | --- |
| 现有计算与点阵 | 4 |
| 比较类单选 | 2 |
| 条件筛选多选 | 2 |
| 对错判断 | 2 |

配比尚未确认，也未经教学实验验证。未知数填空可纳入计算类别，具体子类配额在内容审核后确定。混选年级的配额需同时满足年级范围与题型供给，不能直接把本表作为任意年级组合的保证。

组卷仍须局内不重复、优先避开上一局；只调整候选顺序不应变成一道新题或重置错题奖励资格。新配额无法满足时明确提示，不跨年级补题、不使用草稿、不静默替换题型。原计算挑战在新题型验收前保持现有规则。

现有挑战每题 10 秒。建议新题型先进入不限时练习与错题复习，观察阅读和多次选取所需时间后再接入挑战。本方案不修改倒计时；若需按题型调整时限，另行确认。

挑战接入时，首次多选说明在计时前展示；候选全部可读、可操作后计时。未提交就到期记超时，提交错误才记答错。提交和到期竞争必须只产生一个结果。

## 动态生成与判题设计

- 比较题使用结构化的操作数、关系和条件，不执行表达式字符串。
- 多选先构造符合条件的候选，再构造干扰项，最后打乱；禁止无界随机重试。
- 对错题先生成可验证关系，再构造真、假陈述，并检查最终真值，不能假定随机改数必然使陈述错误。
- 每种生成规则记录数值边界、前置能力、映射、实际题面、干扰项、审核者和时间；规则实质变化需重审和更新版本。
- 生成结果先通过结构与关联检查，再由 `selectExercises` 正式筛选；候选预览继续隔离。
- 单选答案、多选集合、对错真值按实际类型表达，禁止用 `0/1`、逗号字符串或数字总和代替不同答案语义。
- 正确答案由结构化任务和固定候选确定，不另存一套可能失配的手写答案；学习判题不依赖 Canvas、DOM 或动画。
- 一道题的任务、候选和候选身份在作答期间固定；选中、取消、暂停和刷新不重新生成候选。

## 实现影响范围

以下是实施时必须检查的调用链，不表示需要新增同等数量的模块或公共接口。

| 位置 | 需要覆盖的变化 |
| --- | --- |
| `src/learning/models.ts`、`evaluation.ts`、`catalog.ts` | 明确任务与作答类型，扩展纯判题及任务合法性校验；检查现有整数 API 调用方后决定最小接口变化 |
| `src/index.ts` | 核对实际需要导出的类型和函数，不为规划中的题型提前扩大接口 |
| `src/content/` 与内容审核文档 | 核对知识点、映射、稳定 ID 和真实审核范围，不自动沿用旧题审核结论 |
| `generation.ts`、`content.ts` | 候选构造、正式筛选、年级和题型配额、去重及内容指纹 |
| `rules.ts`、`session.ts` | 固定候选、切换选择、提交、整题判定、正确目标可达、计分及截止竞争 |
| `render.ts`、`main.ts`、`web/` | 题面与候选呈现、提交按钮、命中与键盘操作、选中反馈、道具、暂停和复活接线 |
| `learning.ts` | 题目身份、文字与讲解、课程或练习入口、新题型复习 |
| `storage.ts`、`profile.ts` | 新任务与答案校验、候选和未提交选择恢复、错题原题、奖励去重及版本约束 |
| `tests/` 与现有说明文档 | 有意义的边界回归、旧题验证、更新玩法与架构说明，并记录实际验证结果 |

旧成绩、设置、钱包、库存、错题和领奖凭据属于实际持久化约束，不能为新题型清空或重发奖励。实现前检查已有读写与版本逻辑，确定旧局次能否恢复；如必须拒绝不兼容中断局，须明确提示且保留其他档案数据。涉及移除公共接口或持久化格式时，按项目规则列出影响并确认后处理。

新题型错题记录至少能还原结构化原题、固定候选与实际提交答案；任务和选项顺序如何参与稳定身份需显式定义。重复复习、候选重排和规则版本升级不得自动重置同题领奖资格。只有当前审核仍允许的原题才能进入正式复习。

## 实施顺序

1. 确定首批题型、年级与数值范围，审核候选题面和生成规则；确认新练习入口、反馈及复活细则。若调整挑战时限、奖励或正式配额，先确认对应规则。
2. 选择“找出所有比指定数大的数”作为最窄端到端路径，串通正式筛选、不限时作答、整组判题、讲解、错题复习、刷新恢复和离线；使用实际审核内容，不把测试 fixture 当正式内容。
3. 复用已验证的多选路径增加小于题；加入比较单选、比较符号、对错判断和未知数填空，完成首批 8 种题型。
4. 完成不限时体验的实际浏览器验证与教学审核，再按确认规则接入限时挑战、提醒、复活、金币和混合组卷。
5. 首批验收后才开展范围筛选、数位、等值算式、数列和图示题，不同时实施全部目录。

步骤 2 用于验证跨判题、交互与持久化边界的可行性，不能代替首批完整验收。

## 验收条件

| 范围 | 必须取得的证据 |
| --- | --- |
| 数学正确性 | 大于、小于、相等边界，极值唯一性，正确／错误陈述，填空唯一解及全部合法候选检查 |
| 多选判题 | 正确集合通过；漏选、多选均失败；顺序不影响答案；非法、重复或非本题选项身份被拒绝 |
| 正式内容 | 草稿隔离、63 种非空年级组合、不跨年级、配额不足显式提示，规则审核与映射可追溯 |
| 规则与奖励 | 未提交不判题；取消选中不计错；重复提交只计一次；超时与提交竞争；提醒和复活不重复奖励 |
| 存储与复习 | 原题、候选、未提交选择和剩余时间一致恢复；复活重答清空选择；错题实际答案可还原；旧档案和奖励凭据不丢失 |
| 手机交互 | 窄屏和横竖屏题面、候选、提交按钮可见；不以滚动或颜色作为唯一操作线索；查看实际截图并完成操作 |
| 离线与更新 | 缓存后断网重开，完成含新题型的一局并保存；进行中局次不混用内容版本 |
| 完整回归 | `npm run check` 通过，旧计算题完整局、新多选路径和混合局实际浏览器通过；测试与浏览器失败如实记录 |

浏览器模拟、iOS Safari 真机、Android Chrome 真机分别记录。自动数学检查不代替题意、可读性和教学适配审核；截图不能单独证明判题、恢复和离线行为。

## 实施决策与保留限制

- 用户明确授权本次实现全部目录中的 17 类题型；按先打通首批端到端路径、再扩展后续题型的顺序完成。
- 不新增导航入口：新题型进入现有课程和错题复习；原有 5 节课程保留，现共 21 节。挑战每局 10 题和每题 10 秒不变。
- 单年级采用原计算／点阵 4、选择题单选 2、多选 2、判断 2；混选各年级各 5 题。先选不同题型，再选具体候选，按语义身份防止混选年级重复同题。
- 多选固定 6 个候选、2–4 个正确项，整组提交；复活清空选择，暂停／刷新恢复未提交选择。不限时练习可查看漏选、多选和讲解，挑战复活前不披露完整答案。
- 结构化算式选项与等份图示已实现。数位和图示当前只在二年级审核范围内开放；所有题型仍遵守所选年级范围，不为覆盖年级补题。
- 一年级数域以 0–10、二年级以 0–100 为主，具体运算与前置能力按审核记录限定。教材来源与教学映射继续 pending，不宣称教材精确对齐。
- 84 项自动检查通过；全部题型的实际浏览器、布局、课程／错题奖励、恢复和离线结果以扩展验证记录为准，不能只凭测试数量认定完成。
- 教师评审、学生可读性与教学效果、真实设备和生产部署仍未验证；既有 M7 缺口保留，其他游戏未启动。
