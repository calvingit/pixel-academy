# M9 拼音冒险 · 音频来源方案（内容准备）

状态：**已决策并进入实施**（2026-10-27 用户确认：采用方案 A 婷婷 TTS 预生成；音频先批量入库，真人试听作为缺口如实记录，后续试听有问题的条目单独重生成或替换）。未决策前的方案对比与审核边界分析保留如下，供追溯。

## 一、现状核对（已完成）

- **知识点无需新增**：`chinese.pinyin.initials`（声母辨认，MAP-003 → CH-01A-U02「汉语拼音（一）」+ U03）与 `chinese.pinyin.finals`（韵母辨认，MAP-004 → CH-01A-U02 + U04）已在 `src/content/skills.ts`，单元关联为候选状态（source/curriculumVerification: pending）。
- **音频资产为零**：内容基准与仓库中无任何发音音频；M9 验收要求「听辨音频随内容缓存，断网可播放」，音频来源必须产生**可入 SW 预缓存的真实文件**。
- **首版音频范围**：声母 23 + 韵母 24 = **47 个单音节音频**（无调；声调、拼读、整体认读按 PLAN 在各自审核后扩充）。每条 < 1 秒。

## 二、方案对比（A 已实测，其余按文档评估）

### 方案 A：macOS 婷婷（Tingting）语音预生成 WAV 入库 —— 推荐

- **做法**：本机 `say -v Tingting "<字母>"` 逐条生成 AIFF → `afconvert` 转 16-bit 22.05kHz 单声道 WAV，命名 `web/audio/pinyin/<字母>.wav` 入库，随 SW 预缓存交付。
- **实测证据（2026-10-27）**：婷婷语音在本机存在（zh_CN）；生成 0.71 秒 / 35KB 的 WAV 成功；47 条合计约 1.6MB，预缓存体积可接受；链路零网络依赖、可脚本化复现。
- **优点**：文件真实入库 → 断网可播放，**直接满足 M9 验收**；来源单一可控、生成脚本可复现可审计；每条音频与字母一一对应，便于代理核对清单。
- **风险与缺口**：①**发音内容未经真人试听**——TTS 读单个拼音字母的读音（呼读音/本音/是否英化）是教学正确性核心，代理无法替代试听，须留真人试听缺口或由用户抽听；② Apple 系统语音合成输出的再分发许可属灰色地带（系统语音供设备内使用，批量导出音频文件入库传播未见明确授权条款），需要用户知悉并接受；③ 合成音色对低龄儿童的清晰度/友好度未经儿童实测。

### 方案 B：浏览器 Web Speech API 实时朗读（不生成文件）

- **做法**：`speechSynthesis.speak()` 用系统中文语音实时读字母，零资产。
- **优点**：零文件、零许可问题、跨平台自动有声音。
- **缺点（关键）**：Android Chrome 的中文语音多依赖 Google TTS 联网或可下载语音包，**离线可播放无保证**，与 M9 验收「断网可播放」冲突风险高；声音随设备/系统变化，听辨题的正确答案无法与固定音频绑定审核；桌面无中文语音时直接哑。**不推荐作为主方案**；若采纳 A，可在音频加载失败时按 PLAN「音频不可用时明确提示并允许退出或选择可用模式」处理，不引入 B 作为隐性降级。

### 方案 C：教师/家长真人录音

- **做法**：按 47 条清单录制人声 WAV/MP3 入库。
- **优点**：发音权威、音色亲切，教学与审核口径最干净（录音者即审核者）。
- **缺点**：需要用户投入录制与剪辑；首版 47 条工作量可控但依赖人力到位时间。
- 可作为 A 的后续升级路径（音频文件命名与播放层不变，替换文件即可）。

### 方案 D：开源/公有领域音频库（Wikimedia Commons 等）

- **缺点**：拼音单音节覆盖不全（尤其全部 24 韵母），逐条许可与发音质量核对成本高，口径混杂。不推荐。

## 三、推荐与审核边界

**推荐方案 A**，理由：唯一实测可行的、直接满足「断网可播放」验收的自动化路径；方案 C 的录音可随时无感替换升级。

审核边界（按内容维护规则，代理不冒充）：

1. 代理可审：生成脚本与输入清单一致性（47 条音频与拼音字母一一对应、拼写正确、无缺漏重复）、文件格式与体积、时长非零非静音、SW 预缓存清单覆盖。以代理身份记录（zcode-agent）。
2. **必须真人**：发音正确性（呼读音口径）、清晰度与儿童可听性——本方案的最大缺口，无法由代理完成。可选做法：用户抽听（如 10 条）确认婷婷发音可用后再批量入库；或先入库并按 hanzi 先例记录「真人试听未做」缺口。
3. 需用户知悉：Apple 语音输出再分发的许可灰色地带（见方案 A 风险②）。

## 四、关卡拆分与交互约束（M9 首版口径，供规则文档展开）

- **辨认关卡（无声频依赖）**：呈现拼音字母字形 → 从候选中选认（声母辨认 / 韵母辨认分开组卷，按 MAP-003/MAP-004 与年级筛选）。交互复用 choice 判题模式；字体须区分易混字形（b/d、p/q、f/t、n/u 等，PLAN M9 验收「字体能区分易混字形」）。
- **听辨关卡（音频驱动）**：播放音频 → 从候选中选认对应字母；**不得以文字提示泄露答案**（题面不含该字母的字形，装饰文案不含拼音字母表）。音频提供可重复播放按钮。
- **静音/音频不可用降级**：检测 `Audio` 播放失败或系统静音时，听辨关卡明确提示「当前无法播放声音」并允许退出或切换到辨认模式，**不假装完成听力训练**（PLAN 验收原文）。
- 音频随 SW 预缓存：`web/audio/pinyin/` 加入 build-sw 清单（47 条 + 未来扩充位），断网可播。
